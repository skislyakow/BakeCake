# Документация для разработки и ИИ-агентов

Эта директория — рабочая документация проекта. Она нужна для анализа кода,
планирования задач и объяснения принятых решений. Пользовательская документация
находится в корневом [`README.md`](../README.md).

## Что здесь лежит

- [`PLAN.md`](PLAN.md) — техническое задание, архитектура, контракт API, задачи,
  лог решений и история изменений. Это первоисточник по проектным решениям.

## Как этим пользоваться

- Перед изменением поведения сначала проверь `PLAN.md`: возможно, решение уже
  описано и аргументировано.
- `PLAN.md` большой, читай только нужный раздел. Карта разделов — в начале файла.
- Если меняется архитектура, контракт API или правила работы, обновляй `PLAN.md`
  вместе с кодом.
- Не переноси сюда сведения о запуске и эксплуатации, которые нужны человеку:
  их место в корневом `README.md`.

## Проверки

```bash
cd backend
python manage.py check
python manage.py makemigrations --check --dry-run
python -m pyright
python -m pytest
```

Живой смоук приёмки заказа (нужны демо-данные и запущенный сервер; создаёт
тестовые заказы в базе, поэтому запускай на локальной или демо-базе):

```bash
cd backend
python manage.py runserver 127.0.0.1:8123
python ../scripts/smoke_order.py http://127.0.0.1:8123
```

Скрипт повторяет запросы фронтенда по HTTP: конструктор и каталог, расчёт
стоимости, ошибки слота доставки, создание заказа, детали, список, жалобу и
запасной путь с несуществующим `cake_id`.
